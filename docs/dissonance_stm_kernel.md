# Dissonance STM の周波数ペア再利用

`evaluate` と `commit!` は従来どおり毎回、現在の和音と STM 内の各イベントの合成和音を評価する。正規化された音高（12音）と倍音番号から決まる Sethares の指数関数部分だけを、倍音数ごとの行列に一度計算して再利用する。音量、倍音の音量閾値、周波数順のソート、ペアの加算順、過去イベントの重みと除去条件は毎回計算する。和音や記憶イベントを省略しない。

通常の8倍音では 96×96 個の `Float64`（約72 KiB）を共有する。行列は初回利用時に作成し、スレッド間では lock で保護する。倍音数が32を超える、未対応の model、正規化されていない音高を直接渡す場合は従来の計算を使う。manager の deepcopy に行列を含めない。

テストは `julia --project=. test/runtests.jl dissonance_stm_kernel.jl`。従来計算を独立した基準として残し、反復音、異なる音量、和音、閾値付近、記憶の除去、異なる倍音設定の `evaluate` と `commit!` を比べる。浮動小数の許容差は絶対 `1e-10`、相対 `1e-12`。計算式の省略や近似は行わない。

`julia --project=. scripts/benchmark_dissonance_stm.jl` は128/256イベントの反復音と変化する和音について、旧経路と新経路の時間・割当量を記録する。さらに現在音、記憶干渉、除去処理を200回ずつ別計測する。SHA も出力する。これは短い fixture の比較であり、長い MusicAnalyse 全体の所要時間を表すものではない。
